## Один защищённый путь

Подготовлен отдельный public-control workflow `test-db-runtime-report.yml`: только владелец JSMJapan, protected main, exact approved control SHA, attempt1, существующее защищённое окружение `test-api-readonly-access` и подтверждение владельца. Его собственный context проверяется отдельно: private PR29 publisher scope **не подменяется**. `reference_site_sha=4855198…` — reference для исходников, не установленный serving SHA. GitHub policy/run/environment approvals проверяются до существующего pinned key-only TEST transport. Новый workflow вручную не запускался.

Единый временный пакет передаётся через существующий GitHub admin channel. Проверенный zip/bz2 bundle хранится в sealed memfd; root capsule создаёт новый `/run/jsm-db-2760-<random>/` и ровно пять публичных PHP-файлов (root, каталог0711, файлы0644). Это **временные диагностические записи файлов**, без постоянной установки, правок прежнего installer/wrapper, FPM/Apache или приложения. Producer проверяет совпадение directory/file inodes, размеров и hash через стабильный FPM process root. Свежий уникальный каталог исключает старый `.user.ini` cache для этого каталога.

Один прямой local FastCGI request в тот же FPM, вне webroot; фиксированные согласованные CGI поля. Нет PHP_VALUE/PHP_ADMIN_VALUE: в PHP7.4 они меняют worker INI без гарантированного восстановления. ROOT и PHP обмениваются строгими HMAC frame с nonce/context/role/sequence. ROOT проверяет worker PID/UID/принадлежность FPM и запрещает worker UID0 либо `jsm`. PHP до HELLO проверяет kernel peer PID и только его публичные Pid/Uid поля: координатор должен быть root. Секретный nonce не передаётся по Unix dialogue.

## Что наблюдается

1. Текущие stock launch и config-файлы проверяются до PHP: только прямой php7.4-fpm launch; root-owned стабильные фиксированные php.ini/conf.d/php-fpm.conf/pool.d. Проверяются только prepend/append/user_ini/include selectors и безопасный поддерживаемый layout. Main php.ini≤128KiB (официальный stock7.4.33 —72584B); прочие ini/conf≤16KiB, максимум32 conf.d/8pool entries. Три более приоритетных SAPI/binary-directory INI должны отсутствовать. Файлы/INI-директории не должны меняться после старта master. Новые временные PHP-директории не подчиняются этому timestamp gate.
2. **Ни `/proc/PID/environ`, ни systemctl Environment/EnvironmentFiles/PassEnvironment/UnsetEnvironment не читаются.** `effective_ini_selection=NOT_ATTESTED`, `worker_memory=NOT_ATTESTED`. Stock-file guard не доказывает историческую память worker или отсутствие любых действий настроенной платформы. Поздний ini_get — дополнительный отказ, не доказательство отсутствия ранее исполненного prepend. Packaged PHP/FPM и установленный Composer/Yii/Dotenv — явная доверительная предпосылка, не новая аттестация vendor/binary/OPcache. PHP8 dependency lock не назначается TEST PHP7.4 baseline.
3. До constructor проверяются literal grammar private config-файлов, известные first-party entry/main/bootstrap pins и startup shapes. Сохраняются исходные четыре definitions и обычный merge. Стандартные Application/Connection; неизвестные bootstrap/extension/event/behavior/custom log logger отказываются. Каждый FileTarget требует явное `logVars=[]`, безопасный локальный logFile и отсутствие callable prefix/enabled. Три first-party models проверяются по pins и alias/Composer resolver **до require**, затем подтверждается inherited getDb и один и тот же app.db. Не вызываются Application::run, URLmanager/controller/session или бизнес-API.
4. ROOT использует прежний один bounded Docker summary GET с прежними socket/systemd peer guards. Единственный mysql-family candidate и его loopback host port связываются с фиксированным cgroup-v2 `docker-<observedID>.scope/cgroup.procs` (≤16typedPID, exact membership). Никаких Docker inspect/top/exec/logs/Env/Labels/argv/volume contents. Наблюдённый ID не становится доверенным synthetic baseline. Поддерживается DIRECT либо один docker-proxy из фиксированного docker.service cgroup; неизвестный layout отказывается.
5. До PDO open подтверждается local MySQL listener; после native PDO connect — owned PHP/ingress/MySQL TCP relation, с совпадающими network namespaces и полной reciprocal DIRECT либо двухзвенной PROXY связью. Root повторно проверяет identities/listener и peer до ACK. Default FD cap128, init512 только прежнего init binding; target4096, TCP64KiB и все прежние guards сохранены. Новый typed target tcp/tcp6 reader сохраняет полный held-FD stamp; исключает только повторно созданный pathname ctime при прежней inode/owner/mode/link identity и стабильном process start/namespace. Старый reader не меняется.
6. Только после independent peer gate ROOT разрешает один fixed `SELECT DATABASE(), CURRENT_USER(), VERSION(), @@read_only` с фиксированными aliases. Native PDO использует исходные target/credentials внутри PHP, без Yii open/initConnection/events/SET NAMES; custom/persistent/failover/init-command/autocommit=false запрещены. Безопасный target передаётся лишь по private channel; DSN/password/env/SQL errors не выводятся. Ответ: schema-match, principal/version class, server_read_only, query_count1. Нет application rows/aggregates/DDL/DML/SHOW GRANTS/provider calls.

## Бюджеты, cleanup и предел доказательства

Producer deadline≤3s и supplied capsule deadline; capsule сохраняет4s outer cap. Docker proof .75s, read/output/FD caps не увеличены. PDO имеет request-local connect/read timeout1s; это **не гарантия абсолютного завершения произвольно зависшего PDO**. Root deadline ограничивает наблюдение/приём результата; IPC timeout не выдаётся за завершение запроса. Частичная отправка SELECT остаётся `AUTHORIZED_NOT_CONFIRMED`, а не «SQL не было».

`fastcgi_state`: NOT_SENT до попытки отправки, UNCONFIRMED после неё, FINISHED только после корректного END_REQUEST. Cleanup удаляет только собственные неизменённые inode/hash файлы. При незавершённом FastCGI каталог становится0700 и cleanup честно UNCONFIRMED; не удаляется чужой/неподтверждённый файл ради зелёного результата.

Успех показывает **configured-runtime FPM→наблюдённое local DB metadata**, при принятой платформенной предпосылке. Он не доказывает фактический произвольный пользовательский Apache request. Synthetic provenance, grants и egress isolation остаются UNKNOWN; DB isolation NOT_ESTABLISHED. Нельзя использовать formatter/константы binding вместо наблюдений.

## Проверки и статус

Синтетические fixtures вызывают actual protocol/root coordinator, typed proc reader, FPM staging consumer и creator; проверяют неправильный peer/startup/nonce, tuple alias в другом namespace, root/publisher UID, caps/metadata drift, CGI bootstrap на неизменённых методах Yii и Dispatcher canary. Нативный PHP syntax/codec/coordinator/model fixtures обязателен на Linux CI. На Mac PHP отсутствует: SKIP, не PASS. Native Linux proc regression воспроизводит прежний ctime отказ и новый narrow-reader успех без raw proc output. Эти тесты не открывают TEST/FPM/MySQL и не доказывают actual PHP7.4/DB runtime.

Статус до итоговых exact-head CI/двух независимых review: DRAFT / NOT READY. Root координирует запись задачи и будущий отдельный допуск. Этот кандидат не требует дополнительного metadata runtime перед отдельно согласованным чистым TEST. Никаких merge/manual workflow/server/SQL запусков автор не выполнял.
