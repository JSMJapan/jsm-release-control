## Ограниченный контракт

- Новый manual workflow `prod-front-sha-readonly.yml`, без inputs; только
  owner `JSMJapan`, main, первая попытка, workflow SHA = checkout SHA.
- Существующее защищённое окружение `apache-parity-bootstrap`, sole-owner
  approval, main-only и запрет admin bypass проверяются прежним `policy_ready`.
  Секрет `APACHE_BOOTSTRAP_ADMIN_SSH_KEY` и переменная
  `APACHE_BOOTSTRAP_KNOWN_HOSTS` не создаются, не меняются и не выводятся кодом.
- Неизменённые `bounded_ssh`, `private_file` и исходный SHA256 trusted host pin
  переиспользуются из admin probe. Та же concurrency group исключает
  одновременные admin-probe и этот запуск. Другие deploy writers этим не блокируются.
- Ровно `/var/www/jsmjapan.com-front/` и три фиксированных относительных пути
  ниже. Пути/команды/expected hashes не принимаются от dispatch или сервера.
  Capsule передаётся по stdin, выполняется только Python `-I -B`.
- Только descriptor-based чтение SHA256: `O_NOFOLLOW` каждого родителя,
  regular single-link file, не более 1 MiB на файл, проверка стабильности
  inode/размера/mtime/ctime до и после. Linux `O_NOATIME` обязателен для реального
  запуска. Файлы/каталоги на сервере не создаются, source bytes не покидают VPS.
- Нет PHP, HTTP, приложения, БД, proxy/provider/translation/AI вызовов,
  установки, reload, записи доступа, генерации/смены ключей, подписей выпуска.
- SSH stderr отбрасывается. Forced-command/auth/key/hostpin отказ завершает
  проверку; другого ключа, shell, provider terminal или обхода нет.
- Output: closed JSON version `jsm-prod-front-sha-v1`, фиксированные пути,
  type/SHA256 и сравнение с историческим expected. Nonce/root/shape/duplicate
  keys/размер проверяются перед выводом. Missing/type/drift = `BLOCKED`, exit1.
  При drift допускается только разбор факта, не автоматическая замена expected.

## План и проверка

1. RED: behavioural tests отказывают без bounded reader.
2. GREEN: исполнить реальный capsule на временных трёх файлах, проверить
   digest-only output, missing/symlink/hardlink/directory/oversize/race отказ;
   closed-schema/nonce/root и missing/drift gate; policy/hostpin до transport;
   сохранение key-only transport и очистку локальных temporary copies.
3. Полный существующий `python3 -B -m unittest discover -s tests -p 'test_*.py'`;
   YAML/JSON parse и diff review. Linux `O_NOATIME` в CI проверяется отдельно;
   macOS fixture явно маскирует лишь отсутствующий platform flag.
4. Root/независимое review, exact CI и допустимый merge. **До этого не запускать.**
5. Только после конкретного одобрения нового scope — один manual main run с
   обычным environment approval, closed receipt прочитать и сохранить в
   существующем private release journal без исходников/секретов.

Новая проверка расширяет фиксированное наблюдение admin key с двух Apache stat
на три source digest. Это подготовленный для review scope, не уже выданное
разрешение запускать диагностику или выпуск. Production и ключи не менялись.
