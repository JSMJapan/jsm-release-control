# #2760 — получение зашифрованной копии установщика TEST

23.11.2026 JST. Цель — получить копию одного установленного файла для последующей закрытой проверки точки подключения отчёта PR №29. Цель запуска: [Google Compute Engine, jsm-sandbox](https://console.cloud.google.com/compute/instancesDetail/zones/asia-northeast1-a/instances/jsm-sandbox?project=dark-berm-508215-d2), ID 150919059249400713, домен develop.jsmjapan.com. Журнал работы: [#2760](https://github.com/JSMJapan/jsm-storefront/issues/2760#issuecomment-7073968658).

Разрешена подготовка кода. Слияние и первый запуск из main согласуются отдельно по проверенному коммиту, отпечатку получателя и назначению артефакта. Используется прежнее защищённое окружение test-api-readonly-access, когда действуют его требование ревью владельца, привязка только к main и запрет обхода администратора. Перед обращением к VM требуется точный ввод SHA проверенного main и закреплённого SHA-256 файла публичного сертификата. Оператор заранее подтверждает, что соответствующий закрытый ключ остаётся доступен на локальной машине и не передаётся в GitHub или на VM. Повторные попытки одного запуска заблокированы.

Операция ограничена /usr/local/sbin/jsm-sandbox-deploy, файлом размером до 8192 байт. Перед чтением VM проверяет закреплённый публичный сертификат и поддерживаемый профиль CMS в системном OpenSSL 3 на публичном образце. Открытие компонентов пути и файла использует дескрипторы с запретом символьных ссылок. Допустим обычный файл с одним жёстким именем, принадлежащий root и недоступный для записи другим пользователям. Замена или изменение файла во время съёмки приводит к отказу. Файл не исполняется. SQL, .env, конфиги приложения и хранилища секретов не входят в область запуска.

CMS DER использует AES-256-GCM и RSA-OAEP с SHA-256 и MGF1 SHA-256. Исходные байты подаются OpenSSL через стандартный ввод внутри VM и не помещаются в аргументы, файлы или вывод GitHub. Артефакт содержит единственный CMS DER файл, хранится один день и доступен читателям публичного репозитория. Если в установщике есть встроенный секрет, его байты защищены тем же CMS шифрованием. Ошибка политики, инструмента, файла, шифрования, транспорта или проверки ответа блокирует публикацию. Рабочие процессы и лимиты существующей диагностики #2760 остаются прежними.

После разрешённого запуска оператор сверяет SHA-256 CMS файла с закрытым по схеме результатом Actions, расшифровывает локально в каталог с правами 0700 и использует результат только после успешной проверки тега GCM. Любой частичный вывод расшифровки удаляется без просмотра. Исторический отпечаток из инвентаризации можно сверить локально после расшифровки. Исходный текст, закрытый ключ и любые обнаруженные секреты остаются вне GitHub и рабочих папок репозитория.

Готовность этого workflow не подтверждает изоляцию БД. PR №29 и последующий запуск Telegram в #2771 сохраняют отдельные требования по проверке активной базы TEST, её прав, происхождения данных и отделения от production.
