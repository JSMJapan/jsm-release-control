# Изолированный TEST Евы для #1620

Кандидат GitHub Actions устанавливает временный профиль только на Google Cloud VM `jsm-sandbox`, проект `dark-berm-508215-d2`, зона `asia-northeast1-a`, VM ID `150919059249400713`. Источники приложения находятся в [PR #2791](https://github.com/JSMJapan/jsm-storefront/pull/2791). Нативная проверка закрытой сборки использует синтетические FAQ, настоящие PHP и MySQL и тестовые адаптеры Telegram и Claude.

## Согласуемая установка

- Точный публичный коммит проверяет ручной запуск владельцем из защищённой ветки `main`, первую попытку и разрешение владельца в отдельном окружении `eva-isolated-stage-1620`. Политика окружения требует владельца JSMJapan, только `main` и запрет обхода администратором.
- `STOREFRONT_ACTIONS_READ_TOKEN` в этом окружении читает Actions частного `JSMJapan/jsm-storefront`. Манифест в `scripts/eva_test_pins.json` закрепляет коммит, номер запуска, номер артефакта и SHA-256 файла. GitHub переносит байты напрямую в каталог закрытого приёмника. В логах только квитанция; приватный ZIP остаётся закрытым.
- Отдельный пользователь `jsm-eva-stage` принимает ровно `jsm-eva-test-1620-v1` через forced command. Ключ ограничивается этой командой, без PTY, агента и перенаправлений. В sudoers разрешается только точная команда из `eva_test_forced_command.sh`. Операция `BOOTSTRAP` в этом workflow устанавливает приёмник через действующий защищённый GitHub admin-канал. Она требует отдельного подтверждения в `test-api-readonly-access`, публичный Ed25519-ключ и его утверждённый SHA-256. Старые ключи, приёмник статей и файл штатного установщика не используются.
- Приёмник и его зависимости устанавливаются с владельцем root в `/usr/local/libexec/jsm-eva-test-1620`. Приёмник сверяет защищённый `control.sha` и метаданные GCE. В отдельном GitHub environment хранятся `EVA_STAGE_SSH_KEY` и переменная `EVA_STAGE_KNOWN_HOSTS` с существующей публичной привязкой точного хоста. Для Евы ещё требуется выполнить `BOOTSTRAP` с согласованным ключом.
- Установщик проверяет постоянно включённый таймер восстановления, затем вооружает дедлайн до первого байта архива. Ресурсы и состояние находятся только в `/var/lib/jsm-eva-test-1620/<run>`. Профиль живёт до 20 минут. Откат использует ID запуска и подтверждает принадлежность контейнеров и образов. Неполный импорт удаляет закрытый архив и сохраняет только служебную запись для восстановления.
- `STAGE` проверяет ограниченные права роли на две таблицы, единственную MySQL в loopback и фактическую PDO-привязку PHP. Квитанция `STAGED_LOCAL_ONLY` означает, что внешний клиент не подключён. `CLEANUP` удаляет только ресурсы этого запуска и проверяет результат.

## Отдельный HTTPS и Telegram

Операция `STAGE_LIVE` требует проверенной политики в `eva_test_live_policy.json`. Кандидат `existing-apache` использует действующий TLS `develop.jsmjapan.com` и добавляет два точных маршрута `/__eva_test_1620/gate` и `/__eva_test_1620/teacher`. Закрытый шлюз работает через отдельный loopback-порт и Unix-сокет. Путь cookies ограничен новым маршрутом моста. Исходные `/__gate`, `/api`, DNS и сертификат сохраняют существующую привязку.

[Историческая квитанция GitHub](https://github.com/JSMJapan/jsm-storefront/blob/e24278e21163b365ed3a67cb9623a4efb705f99d/docs/releases/promo-636/integration-2026-10-23.json) называет `jsm-sandbox-443.conf` и его SHA-256 на 23.10.2026. Перед установкой нужны свежие метаданные активного TLS vhost, действующего сертификата и общего lock publisher. При установке сверяются исходный SHA и безопасные настройки журнала, затем выполняются синтаксическая проверка и graceful reload. Откат возвращает сохранённые байты действующего vhost только при ожидаемом SHA установленной вставки. Вторичный IPv4 остаётся необязательным вариантом для заранее настроенного отдельного TLS.

В режиме `STAGE_LIVE` хост использует четыре новых защищённых входа `EVA_ISOLATED_GATE_USERNAME`, `EVA_ISOLATED_GATE_PASSWORD`, `EVA_ISOLATED_BRIDGE_SECRET`, `EVA_ISOLATED_ANTHROPIC_KEY`. Поток SSH переносит их напрямую в закрытый приёмник. Профиль, сертификат, Claude relay и входной сокет ограничены отдельным каталогом и сроком. PHP и MySQL сохраняют общую изолированную сеть с одним loopback. Relay использует только закреплённый адрес и HTTPS Claude. Очистка останавливает свои службы, отзывает личные файлы доступа и удаляет собственные контейнеры и образы.

Приватный workflow запускает одну синтетическую последовательность в личном чате владельца после успешного `STAGE_LIVE`, проверенного по метаданным GitHub. Существующие токен и ID остаются в `eva-teacher-test`. До polling сверяется числовой ID выделенного TEST-бота, блокируется webhook и при посторонней очереди offset не повышается. Только пары шлюз/мост для временного профиля хранятся одинаково в двух защищённых средах. Ключ Claude остаётся только у защищённого установщика. В отчёте цикла указываются сохранение, два ответа модели и изменение текста без публикации переписки. Смысл ответа подтверждает владелец. Живые вызовы и установка на VM пока не выполнялись.

Проверки и подтверждение установки фиксируются в существующих [#1620](https://github.com/JSMJapan/jsm-storefront/issues/1620) и [#2760](https://github.com/JSMJapan/jsm-storefront/issues/2760).
